# 구현 계획 — Streamlit + FastAPI + SQLite

작성: 2026-09-02  
개정: 과제 역할(`/summarize`, `chat_history`)과 Part 1 도면 기능을 함께 맞춤.  
상태: 계획만. 이 문서 승인 전에는 앱 코드를 옮기지 않는다.

---

## 0. 결정 (역할 vs Part 1)

과제 뼈대와 Part 1을 **둘 다** 지킨다. 요약 전용 앱으로 바꾸지 않는다.

| 과제 이름 | 이 프로젝트에서의 의미 |
|-----------|------------------------|
| 사용자 문서 | 부품 설명 한국어 텍스트 (기존 입력창) |
| `POST /summarize` | OpenAI로 텍스트 → Spec JSON. 기존 파싱. 일반 문서 요약이 아님 |
| `/chat` | **구현하지 않음.** 스펙 추출은 `/summarize`만 사용 |
| Backend 응답을 화면에 출력 | Spec을 기존 확인 표·JSON expander에 표시. 도면은 확인 후 `/render` |
| `chat_history` | 입력 원문, AI 응답(Spec JSON 문자열), 생성 시간. 히스토리 UI는 만들지 않음 |
| Part 1 유지 | 확인 게이트, 치수 표, 원기둥 단 편집, Pillow PNG 미리보기·다운로드 |
| 배포 | 하지 않음. 로컬만 |

`/summarize`만 두면 도면이 빠지므로, Part 1용으로 **`POST /render`를 추가**한다. 과제에 없는 이름(`/api/parse` 등)은 쓰지 않는다.

## 1. 현재 상태 (분석)

### 1.1 실행 구조

지금은 **단일 프로세스**다. `streamlit run app.py`가 UI·OpenAI 호출·Pillow 렌더를 모두 한다.

| 파일 | 역할 |
|------|------|
| `app.py` | Streamlit UI. 입력, 치수 확인, 단 추가, 미리보기/다운로드 |
| `openai_parse.py` | OpenAI Chat Completions. 텍스트 → Spec JSON. 키는 `.env` |
| `spec_schema.py` | Pydantic `SpecDraft`, 원기둥 steps/공차 |
| `drawing.py` | Pillow PNG |
| `.env` | `OPENAI_API_KEY`, `OPENAI_MODEL`, (선택) `OPENAI_BASE_URL` |
| `requirements.txt` | streamlit, python-dotenv, openai, pydantic, Pillow |

DB 없음. 스펙·PNG는 `st.session_state`에만 있다.

### 1.2 유지해야 할 기능·UI (`app.py`)

- 히어로, 입력창, ↑ 스펙 추출, 전체 폭 **사용 방법**
- 파싱 전 도면 없음. 확인 후 도면 생성
- box / plate / cylinder(단·공차) 확인 UI
- JSON expander, PNG 미리보기·다운로드
- 기존 CSS·문구

### 1.3 문서

앱 실행에 필요한 문서는 `README.md`와 이 구현계획만 둔다. 예전 `PROMPT_SUMMARY.md`는 삭제했다. Strategy와 D1·D2, 원기둥 예외는 코드에 그대로 있다.

## 3. 파일별 역할

### 3.1 `frontend/app.py`

- Streamlit UI만 담당. 화면·세션·확인 게이트는 기존과 동일.
- 사용자 텍스트를 받는다 (기존 textarea).
- **스펙 추출(↑):** `POST {BACKEND}/summarize` (`{ "text": "..." }`).
- 응답의 `spec`(및 요약 한 줄이 있으면 notes)을 확인 표에 그린다.
- **확인 후 도면 생성:** `POST {BACKEND}/render` (`{ "spec": ..., "history_id": ... }`). PNG를 미리보기·다운로드.
- OpenAI SDK·Pillow·API 키를 쓰지 않는다.

### 3.2 `backend/main.py`

- FastAPI 서버. 루트에서 `uvicorn backend.main:app --reload --port 8000`.
- `POST /summarize`: 기존 `parse_text_to_spec`로 OpenAI 호출. 성공 시 `chat_history`에 저장.
- `POST /render`: 확정 Spec으로 Pillow PNG. Part 1 유지용. 과제에 없는 경로이지만 도면에 필요.
- `GET /health`: `{ ok, has_openai_key }`.
- `/chat`은 두지 않는다.

응답 예 (`/summarize`):

```json
{
  "id": 1,
  "input": "원문",
  "response": "{ ... Spec JSON 문자열 ... }",
  "spec": { },
  "created_at": "2026-09-02T13:00:00"
}
```

`response`는 DB에 넣는 AI 응답과 같다. 프론트는 `spec` 객체를 폼에 쓴다.

### 3.3 `backend/database.py`

- SQLite 연결, `init_db()`로 테이블 생성.
- **필수:** `chat_history` — 입력, AI 응답, 생성 시간.
- **추가:** `drawings` — PNG는 `chat_history` 텍스트 컬럼에 넣지 않음.

```sql
CREATE TABLE chat_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  input TEXT NOT NULL,
  response TEXT NOT NULL,
  created_at TEXT NOT NULL
);

CREATE TABLE drawings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  history_id INTEGER,
  spec_json TEXT NOT NULL,
  png BLOB NOT NULL,
  title TEXT,
  created_at TEXT NOT NULL,
  FOREIGN KEY (history_id) REFERENCES chat_history(id)
);
```

- `save_chat(input_text, ai_response) -> id`
- `save_drawing(spec, png, history_id=None) -> id`

UI에 히스토리 목록은 만들지 않는다. 저장만 한다.

## 4. 책임 분리

```text
[브라우저]
    ↓
[Streamlit frontend/app.py]     UI + session_state
    ↓ POST /summarize , POST /render
[FastAPI backend/main.py]
    ├─ openai_parse.py          OPENAI_* 는 여기만
    ├─ drawing.py               PNG
    └─ database.py              chat_history, drawings
```

- 키는 FastAPI만 `.env`에서 읽는다.
- 확인 없이 summarize+render 원샷 금지. 흐름: 추출 → 표 수정 → 확인 후 생성.

## 5. API

| 메서드 | 경로 | 요청 | 응답 | 실패 |
|--------|------|------|------|------|
| GET | `/health` | — | `{ ok, has_openai_key }` | — |
| POST | `/summarize` | `{ "text": "..." }` | `{ id, input, response, spec, created_at }` | 400 빈 텍스트, 503 키 없음, 422 파싱/스키마 |
| POST | `/render` | `{ "spec": SpecJSON, "history_id"?: int }` | `image/png` + `X-Drawing-Id` | 422 unsupported/치수 부족, 500 렌더 실패 |

- `/summarize` 성공 시 `chat_history`에 `input=text`, `response=Spec JSON 문자열`, `created_at` 저장.
- `/render`는 프론트가 수정한 spec을 보낸다. 서버에서 `normalize_spec` + `missing_dimension_labels` 재검증 후 PNG.
- 렌더 성공 시 `drawings`에 저장.

CORS: `http://localhost:8501` 허용.

환경변수 (선택, 기본값으로 로컬 동작):

```
BACKEND_URL=http://127.0.0.1:8000
SQLITE_PATH=backend/data/app.db
```

기존 `OPENAI_API_KEY` / `OPENAI_MODEL` / `OPENAI_BASE_URL`은 그대로. 배포용 변수는 넣지 않는다.

## 6. Frontend 호출 교체

**유지:** `PAGE_CSS`, 히어로, 위젯 키, `form_rev`, 단 편집, 확인 게이트, 에러 문구.

**제거:** `parse_text_to_spec`, `render_drawing_png` 직접 호출, 프론트의 키 검사.

**추가:**

```python
BACKEND = os.getenv("BACKEND_URL", "http://127.0.0.1:8000")

def api_summarize(text: str) -> dict:
    r = requests.post(f"{BACKEND}/summarize", json={"text": text}, timeout=60)
    ...

def api_render(spec: dict, history_id: int | None) -> bytes:
    r = requests.post(f"{BACKEND}/render", json={"spec": spec, "history_id": history_id}, timeout=60)
    ...
```

- `run_parse` → `api_summarize`. `session_state.history_id`에 `id` 저장.
- `start_render` → `api_render`.
- 스키마 폼: `spec_schema.py`는 `backend/`에 두고 frontend는 `sys.path`로 `CylinderStep` 등만 import (선택 A). Pillow/OpenAI는 import하지 않음.

## 9. 구현 순서

1. `backend/` 패키지, 기존 모듈 이동
2. `database.py` (`chat_history`, `drawings`) + `main.py` (`/summarize`, `/render`, `/health`)
3. `frontend/app.py` UI 이전, HTTP 교체
4. 루트 중복 파일 삭제
5. `requirements.txt`, `.gitignore`(`*.db`, `backend/data/`), README (로컬 두 프로세스)
6. 수동 확인: 상자 summarize → 확인 → PNG / 2단 원기둥 / 키 없을 때 503 / 확인 전 도면 없음 / `chat_history` 행 생성

## 11. 리스크

| 리스크 | 대응 |
|--------|------|
| `/summarize`를 글 요약으로 오해 | 응답은 Spec JSON. UI는 기존 확인 표 |
| 과제에 `/render`가 없음 | 없으면 Part 1 PNG가 불가. 로컬 전용 추가 경로로 둔다 |
| 루트 `app.py`를 계속 실행 | 루트 파일 제거, README는 `frontend/app.py` |
| 프론트 폼에 SpecDraft 필요 | backend `spec_schema`만 공유 import |

이 계획으로 구현을 진행하면 된다.
